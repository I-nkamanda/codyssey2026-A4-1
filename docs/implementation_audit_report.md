## 4. 코드 및 데이터 관점의 추가 개선 포인트

사전평가 항목 외에, 실제 코드([main.py](../main.py))와 데이터([generate_data.py](../generate_data.py))를 검토했을 때 개선하면 좋은 기술적 포인트입니다.

1. **검색 시 매번 재학습되는 구조 (`main.py:52-58`)**
   - `search(query, topk)`를 호출할 때마다 `load_data()`로 CSV를 읽고 `Tfidf().fit(texts)`와 `vectorizer.transform(texts)`를 매번 새로 계산합니다.
   - **개선**: 한 번 계산한 어휘 사전, IDF, 문서 행렬을 메모리에 캐싱하거나 파일로 저장해 재사용하도록 개선할 수 있습니다.
2. **밀집 행렬(Dense Matrix) 사용 (`main.py:29`)**
   - 현재 어휘가 33개라 문제가 없지만, 실제 데이터셋에서는 어휘가 수만 개로 늘어나 `np.zeros((N, V))`가 막대한 메모리를 차지합니다.
   - **개선**: 문서가 커질 경우 0이 아닌 값만 저장하는 방식이나 역색인 구조로 전환이 필요합니다.
3. **합성 데이터의 구조적 한계 (`generate_data.py:18-24`)**
   - 모든 리뷰가 `주어1+평가1 + 접속사 + 주어2+평가2` 구조로 생성되며, 70% 확률로 긍정/부정 표현이 한 문장에 섞입니다. BoW 모델 입장에서는 앞뒤 문맥과 주된 평가의 비중을 구분할 단서가 거의 없어 정확도가 약 63.3%에 머물게 됩니다.
   - **개선**: NSMC(네이버 영화 리뷰) 등 실제 공개 데이터셋이나 20 Newsgroups를 추가로 실험해 비교 리포트를 남기면 학습 효과가 훨씬 높아집니다.
4. **파일 정리**
   - 현재 `README.md`, `README 2.md`, `MANUAL.md`, `DEMO.md`로 문서가 분산되어 있습니다. `README 2.md`의 내용을 기반으로 누락된 항목(#7, #14, #15, #16 등)을 보강하여 `README.md`로 일원화하는 것을 권장합니다.
