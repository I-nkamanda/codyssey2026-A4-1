# 📘 반복문만 알면 이해하는 A4-1: 나만의 문서 검색기 원리

이 학습 자료는 **`for`문과 `if`문, 리스트/딕셔너리 정도만 다룰 줄 아는 코더**가 현재 프로젝트([main.py](../main.py))의 원리와 한계를 완벽하게 이해할 수 있도록 작성했습니다.

## 🎯 이 프로젝트가 해결하려는 질문
> **"컴퓨터는 글을 읽고 뜻을 이해할 줄 모르는데, 어떻게 내가 원하는 문서를 찾아주고 긍정/부정도 맞힐 수 있을까?"**

정답은 생각보다 단순합니다. **글을 단어로 쪼개서, 각 단어가 몇 번 나왔는지 '숫자 표(벡터)'로 바꾼 뒤 숫자의 비슷함을 계산**하는 것입니다!

## 1단계: 문장 쪼개기 (토큰화와 불용어)

컴퓨터에게 `"극장에서 봤는데 연기 좋았다!"`라는 문장을 주면 통째로 비교하기 어렵습니다. 그래서 먼저 단어 조각(**토큰, Token**)으로 나눕니다.

### 코드로 이해하기 (`main.py` 12~17줄)
```python
STOPWORDS = {'이', '그', '저', '것', '수', '정말', '너무', '그냥', '그리고', '하지만', '영화'}
TOKEN = re.compile(r'[가-힣a-z0-9]+')

def tokenize(text):
    return [w for w in TOKEN.findall(text.lower()) if w not in STOPWORDS]
```

반복문으로 풀어서 쓰면 아래와 똑같습니다:
```python
def tokenize_easy(text):
    # 1. 소문자로 바꾸고, 한글/영어/숫자만 덩어리로 뽑아냅니다. (특수문자 !, 쉼표 등은 제거됨)
    words = TOKEN.findall(text.lower())
    
    # 2. 불용어(STOPWORDS)에 없는 단어만 새 리스트에 담습니다.
    result = []
    for w in words:
        if w not in STOPWORDS:
            result.append(w)
    return result
```

* **불용어(Stopwords)란?** `"영화"`, `"정말"`, `"그리고"`처럼 거의 모든 리뷰에 등장해서 문서를 구별하는 데 도움이 안 되는 단어들을 미리 빼는 목록입니다.
* **주의할 점 (현재 코드의 한계)**:
  * 한국어는 조사가 붙기 때문에 `"연기"`와 `"연기가"`를 서로 다른 단어로 봅니다.
  * `"하지만"` 같은 접속사도 불용어로 빼버렸는데, `"연기 좋았다 하지만 결말 아쉬웠다"`에서 앞뒤 문장의 반전을 알 수 있는 힌트가 사라지는 부작용이 생깁니다.

## 2단계: 단어를 숫자로 바꾸기 (TF-IDF)

단어를 쪼갰다면 이제 점수를 매길 차례입니다. 단순히 "단어가 많이 나온 문서가 최고!"라고 하면 문제가 생깁니다. 모든 리뷰에 다 들어있는 흔한 단어(예: `"봤는데"`)가 점수를 독차지하기 때문입니다.

그래서 **TF-IDF**라는 아이디어를 씁니다.

1. **TF (단어 빈도)**: 이 문서 안에 그 단어가 몇 번 나왔는가? (많이 나올수록 관련 있음)
2. **DF (문서 빈도)**: 전체 문서 중 그 단어가 등장한 문서가 몇 개인가?
3. **IDF (역문서 빈도)**: 흔한 단어는 점수를 깎고, 드문 단어는 점수를 높여주는 가중치!

### 🧮 작은 예시로 손계산 해보기
전체 리뷰가 3개 있다고 해봅시다.
* 리뷰 1: `"연기 좋았다"`
* 리뷰 2: `"연기 별로였다"`
* 리뷰 3: `"연기 반전"`

여기서 `"연기"`는 3개 문서 모두에 나오고(`DF = 3`), `"반전"`은 1개 문서에만 나옵니다(`DF = 1`).
`main.py`의 IDF 공식은 다음과 같습니다:

$$\text{IDF} = \log\left(\frac{1 + \text{전체 문서 수}}{1 + \text{DF}}\right) + 1$$

* `"연기"`의 IDF = $\log((1 + 3) / (1 + 3)) + 1 = \log(1) + 1 = \mathbf{1.0}$
* `"반전"`의 IDF = $\log((1 + 3) / (1 + 1)) + 1 = \log(2) + 1 \approx \mathbf{1.69}$

> **💡 왜 `log`와 `+1`을 쓸까?**
> - **분모/분자 `+1` (스무딩)**: 만약 어떤 단어가 0번 등장해도 분모가 `0`이 되어 나누기 에러가 나지 않게 막아줍니다. 뒤의 `+1`은 모든 문서에 다 나오는 단어라도 점수가 `0`이 되어 아예 사라지는 걸 막아줍니다.
> - **`log` (로그)**: 문서가 100만 개일 때 1번 나온 단어와 100만 번 나온 단어의 차이가 100만 배가 되면 계산이 망가집니다. `log`를 씌워 숫자 차이를 완만하게 줄여줍니다.

### 코드로 이해하기 (`main.py` 20~39줄)
`Tfidf` 클래스는 **행이 문서, 열이 단어**인 커다란 2차원 표(행렬)를 만듭니다.
* `fit(documents)`: 모든 문서를 훑어서 **단어 사전(`vocabulary`)**을 만들고 각 단어의 **IDF**를 계산해 저장합니다.
* `transform(documents)`: 각 문서마다 `[단어1 점수, 단어2 점수, ...]` 형태의 숫자 리스트(벡터)를 만들고, 문서 길이에 따른 유불리를 없애기 위해 벡터의 전체 길이를 `1`로 맞춥니다(**L2 정규화**).

## 3단계: 비슷한 문서 찾기 (코사인 유사도)

이제 검색어(`query`)도 똑같이 숫자 리스트로 바꾼 뒤, 1,200개의 리뷰 숫자 리스트와 하나씩 비교해서 가장 비슷한 Top 5를 뽑습니다.

### 🏹 화살표 방향 비유
* **유클리드 거리**는 두 점 사이의 직선 거리를 잽니다. 긴 글과 짧은 글은 단어 횟수 차이 때문에 거리가 멀어지기 쉽습니다.
* **코사인 유사도**는 두 숫자 리스트가 가리키는 **화살표의 방향**이 얼마나 같은지(각도) 잽니다.
  * 완전히 같은 방향이면 `1.0`
  * 겹치는 단어가 하나도 없으면 `0.0`

```python
# main.py 42~44줄
def cosine(query, matrix):
    denominator = np.linalg.norm(matrix, axis=1) * np.linalg.norm(query)
    return np.divide(matrix @ query, denominator, out=np.zeros(len(matrix)), where=denominator != 0)
```
* `matrix @ query`: 두 벡터의 같은 자리 숫자끼리 곱해서 모두 더합니다(내적).
* `denominator`: 두 벡터의 길이(노름)를 곱해서 나눕니다. (이미 정규화가 되어 있다면 내적만 해도 됩니다!)

## 5단계: 왜 36.7%나 틀렸을까? (BoW의 한계)

테스트셋 240개 중 88개(`44 + 44`)를 틀린 실제 사례([results/metrics.json](../results/metrics.json))를 직접 살펴봅시다.

* **`review-0775`** (실제: 부정 `0`, 예측: 긍정 `1`)
  > `"기대하고 봤는데 연기 만족스러웠다 하지만 액션 아쉬웠다"`
* **`review-0323`** (실제: 부정 `0`, 예측: 긍정 `1`)
  > `"끝까지 봤는데 스토리 인상적이었다 하지만 결말 실망스러웠다"`

### 🔍 왜 이런 일이 벌어질까?
현재 방식은 문장의 단어들을 주머니(**Bag of Words, BoW**)에 넣고 흔든 뒤 개수만 세는 것과 같습니다.
1. **어순과 문맥 무시**: `"고양이가 쥐를 잡았다"`와 `"쥐가 고양이를 잡았다"`는 단어 구성이 똑같아서 컴퓨터 눈에는 완전히 같은 문장입니다.
2. **긍정/부정 혼재**: `"연기 만족스러웠다"`(+점수)와 `"액션 아쉬웠다"`(-점수)가 한 문장에 같이 들어있으면, 컴퓨터는 **어느 쪽이 진짜 핵심 평가인지** 문맥을 모른 채 단순 합산으로 찍게 됩니다.
3. **동음이의어 문제**: `"사과를 먹었다"`와 `"진심으로 사과했다"`의 `"사과"`를 같은 단어로 취급합니다.

### 🚀 다음에는 무엇을 배울까? (개선 방향)
* **한국어 형태소 분석기 (Kiwi, Okt 등)**: `"연기가"`, `"연기를"`을 모두 `"연기"`라는 하나의 어근으로 묶어 검색 정확도를 높입니다.
* **N-gram**: 단어 1개씩만 보지 않고 `"마음에 들지"`, `"결말 아쉬웠다"`처럼 2~3단어 묶음으로 봅니다.
* **역색인 (Inverted Index)**: 문서가 100만 개가 되면 모든 문서를 다 훑을 수 없습니다. `"단어 → 그 단어가 들어있는 문서 번호 목록"`을 미리 만들어 두면 검색 속도가 엄청나게 빨라집니다.
* **문맥 임베딩 (BERT, LLM 등)**: 단순 빈도가 아니라 문장 전체의 순서와 문맥을 이해하는 최신 AI 모델로 넘어갑니다.

## ✏️ 직접 해보는 미니 실습 (반복문 퀴즈)

아래 두 문장이 있을 때, Python의 `for`문과 `dict`만 사용해서 **단어 빈도(TF) 딕셔너리**를 직접 만들어 보세요!

```python
docs = [
    "연기 좋았다 스토리 좋았다",
    "연기 아쉬웠다"
]

# 목표 출력:
# 문서 0: {'연기': 1, '좋았다': 2, '스토리': 1}
# 문서 1: {'연기': 1, '아쉬웠다': 1}
```

<details>
<summary>정답 예시 보기 (클릭)</summary>

```python
for idx, doc in enumerate(docs):
    tf = {}
    for word in doc.split():
        if word in tf:
            tf[word] += 1
        else:
            tf[word] = 1
    print(f"문서 {idx}: {tf}")
```
이 코드를 조금 더 발전시켜 전체 문서에서 몇 번 나왔는지(DF) 세고, `log`를 씌워 곱한 것이 바로 `main.py`의 `Tfidf` 클래스입니다!
